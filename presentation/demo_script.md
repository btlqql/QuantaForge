# QuantaForge 演示讲稿

建议时长：5–7 分钟。

## 1. 开场：为什么做这个项目

量子计算演示的难点不只是写出线路。用户还需要知道参数是否合理、GPU 是否真实调用、结果是否正确，以及别人能否复现。QuantaForge 的目标是把一句自然语言需求变成一份包含执行、验证和证据的量子实验交付。

## 2. 展示 Agent 计划

在网页输入：

```text
用5个量子比特运行Grover搜索，目标状态为10110，在CPU和壁仞GPU上对比并验证结果。
```

先点击“先看实验计划”。说明系统没有立刻生成任意代码，而是得到白名单 `ExperimentSpec`，并给出理解、检查、构建、执行、验证、报告六步链路。

## 3. 执行 Grover

点击“运行并验证”。重点展示：

- 规范目标状态为 `10110`。
- 实测目标概率为 `0.99918133020401`。
- 与解析理论概率误差为 `9.853e-07`。
- CPU/GPU 目标概率差为 0。
- 结果目录包含线路 SVG、算法日志和结构化 JSON。

说明位序处理：后端原始展示为反序位串，系统保留原始字段并归一化到用户协议位序后验证。

## 4. 展示 QAOA

切换到示例：

```text
用4个量子比特运行QAOA MaxCut，层数2，优化30轮，使用GPU。
```

展示最优割图和收敛曲线。系统得到 `0101`，割值 4；独立验证器枚举 16 个经典候选，确认精确最优值同样为 4，因此近似比为 1.0。

## 5. 展示完整验收

打开 `reports/generated/correctness_report.md`：Bell、GHZ、Grover、QAOA 四个案例全部 PASS。再打开环境报告，指出 Biren106M、SUPA 1.11 与 UnitaryLab 版本。

性能页必须如实讲：正式基准扩展到26比特、预热2次并采集7个稳定态样本，24比特最佳加速比为0.604，当前UnitaryLab 1.0壁仞后端仍未超过CPU。我们没有删除不利数据；实际优化是将约2.91秒GPU初始化移到Web启动阶段，并增加P95、吞吐率、逐次样本和完整状态校验。26比特GPU中位耗时7.52秒，仍远低于单实例10分钟要求。

## 6. 收尾

QuantaForge 的核心不是把聊天框放在量子框架前面，而是用结构化协议和独立验证器约束自然语言，让每次量子实验都有可解释输入、真实执行、明确误差和可复现证据。
