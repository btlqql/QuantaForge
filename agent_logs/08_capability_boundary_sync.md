# 交互 08：能力边界与性能实测同步

**用户目标**：修复网页仍将25比特GHZ误判为超规模的问题，使Agent能力边界与昨日26比特壁仞GPU实测一致。

**Agent行动**：核对源码、性能报告和远端服务后，确认性能基准已覆盖21至26比特，但`ExperimentSpec`仍保留旧的20比特上限。将GHZ公开能力范围统一为3至26，引入集中常量，改用27比特验证结构化拒绝，并同步更新SKILL、README、QA、Web接口测试、验证报告和演示讲稿。进一步发现原实现会把`2^26`个概率和标签全部写入Web JSON，于是保留完整向量验证，但将大规模GHZ响应压缩为两个非零态。

**实测反馈**：26比特GHZ在Biren106M上已有7轮稳定态样本，GPU中位耗时7.519秒，CPU/GPU完整状态最大差异为0；更新后26比特参数校验通过，27比特返回HTTP 422和`CAPABILITY_LIMIT_EXCEEDED`，允许范围明确为3至26。

**决策**：以已经完成的真实壁仞GPU正确性和性能证据作为Agent能力边界，不再维护独立的旧20比特限制；超出实测范围的请求继续在执行前安全拒绝。
