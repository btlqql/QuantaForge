# 场景说明

## 问题

量子模拟通常要求用户同时理解量子算法、框架 API、设备后端和数值验证。教学演示中常见的失败不是“线路不能跑”，而是参数含义不清、GPU 是否实际调用不可证、结果只展示不核验，以及实验难以复现。

## 目标用户

- 希望用自然语言快速演示量子算法的教师和学生。
- 需要比较 CPU 与壁仞 GPU 结果的开发者。
- 需要把算法输出、验证结论和复现证据一次性归档的实验人员。

## 代表性任务

用户输入：

```text
用5个量子比特运行Grover搜索，目标状态为10110，在CPU和壁仞GPU上对比并验证结果。
```

系统输出不是一段代码，而是一个完整实验闭环：

1. 解析算法、规模、目标状态和执行设备。
2. 校验目标串长度和规模上限。
3. 生成六步任务计划。
4. 用 UnitaryLab Algorithms 构建并分别执行 CPU/GPU 实验。
5. 用振幅放大解析公式独立计算理论概率。
6. 比较设备结果、导出线路 SVG、JSON 与 Markdown 报告。

## 展示价值

QuantaForge 将“自然语言交互”与“可检验的科研过程”绑定：自然语言只负责表达意图，确定性协议负责约束，量子框架负责执行，独立验证器负责决定结果能否标记为通过。这样既降低演示门槛，也避免把语言模型生成的解释误当作科学证据。
