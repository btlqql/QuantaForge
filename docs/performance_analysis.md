# 性能分析

## 测试设置

- 任务：8、12、16、20、22、24、25、26 量子比特 GHZ 状态矢量模拟。
- 状态规模：最大 `2^26 = 67,108,864` 个复振幅。
- 设备：同一赛事节点上的 CPU 与 Biren106M（32,512 MiB 显存）。
- 方法：首次执行单独记录；每个设备预热 2 次，再采集 7 个独立稳定态样本。
- 统计：中位耗时、P95、吞吐率；每次都物化完整状态以确保 GPU 工作完成。
- 正确性：同时比较解析 GHZ 概率和 CPU/GPU 完整状态最大差异。

## 主要结果

| 规模 | CPU中位耗时 | GPU中位耗时 | GPU P95 | 加速比 | CPU/GPU状态差 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 20比特 | 0.002410 s | 0.039853 s | 0.041128 s | 0.060 | 0 |
| 24比特 | 0.896814 s | 1.485407 s | 1.504943 s | 0.604 | 0 |
| 26比特 | 2.906168 s | 7.519024 s | 7.776701 s | 0.387 | 0 |

最佳相对表现出现在24比特，加速比为0.604；小于1表示CPU仍然更快。26比特GPU稳定态中位耗时为7.52秒，单实例仍远低于赛事建议的10分钟上限。所有规模CPU/GPU完整状态最大差异均为0。

## 已实施的性能优化

1. Web服务启动时执行一次带解析正确性检查的GPU预热，将约2.91秒的首次后端初始化移到服务启动阶段，避免首个用户实验承担完整冷启动。
2. 将首次执行与稳定态耗时分开，避免把初始化时间混入稳态性能。
3. 从最大20比特扩展到26比特，并增加P95、吞吐率和逐次原始样本。
4. 使用单次独立样本作为正式报告，避免批次内CPU调度抖动制造虚假的GPU优势。
5. 实测了执行器复用、深线路及`complex64`参数；当前UnitaryLab 1.0壁仞后端均未产生稳定加速，因此没有写入不成立的优化声明。

## 结论与边界

当前UnitaryLab 1.0后端在测试负载上没有获得速度加速，GPU价值主要体现在真实壁仞后端接入、跨设备正确性验证、可扩展状态空间以及完整实验闭环。报告保留不利结果，不通过选择性样本夸大性能。
