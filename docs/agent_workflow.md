# Agent / Skill 任务闭环

## 输入到结果

| 阶段 | 组件 | 可观察输出 | 失败策略 |
| --- | --- | --- | --- |
| 理解 | `parser.py` | `ExperimentSpec` | 未识别算法时返回明确选项 |
| 约束 | `models.py` | 通过或具体越界原因 | 不执行不安全或超预算任务 |
| 规划 | `planner.py` | 六步结构化计划 | 计划可先预览，不触发计算 |
| 执行 | `experiments.py` | CPU/GPU 数值与线路产物 | 保留后端错误，不伪造结果 |
| 验证 | `verification.py` | 方法、阈值、误差、PASS/FAIL | 验证失败返回部分成功 |
| 报告 | `service.py` | JSON、Markdown、SVG、日志 | 每次运行使用唯一任务 ID |

## 自然语言的安全边界

解析器不会执行输入中的 Python 或 Shell。它只产生白名单字段：算法、量子比特数、设备、目标态、图边、QAOA 层数和迭代次数。`ExperimentSpec.validate()` 再做范围、图边和字段一致性校验。

## 独立验证

- Bell / GHZ：构造解析概率分布，比较最大绝对误差和概率和。
- Grover：重新计算最优迭代次数与理论目标态概率，并校验找到的二进制串。
- QAOA：枚举小规模图的全部二进制割，计算精确最优割值和近似比。
- 双设备：比较 CPU/GPU 的最终态、目标概率或离散解。

只有独立数值检查通过，`verification.passed` 才能为 `true`。网页中的结论直接来自该结构化字段，不由说明文字推断。

## 可复现性

每次实验都会记录原始自然语言、结构化参数、随机种子、设备、指标、验证阈值、任务 ID 和产物路径。提交包中的 `scripts/validate_correctness.py` 可一次重跑四类验收案例。
